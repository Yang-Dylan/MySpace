# 修复测试用例验证和路由问题

## 概述

修复三个关键问题：
1. 用例执行前校验所有API接口的请求参数都已配置源数据
2. 修复编辑用例保存报错
3. 修复页面跳转后URL未重定向导致刷新报错

## 问题描述

### 问题1：用例执行前缺少参数配置校验
- **现状**：用例执行时，如果API的请求参数没有配置源数据（字段映射），执行会失败或产生错误结果
- **需求**：执行前校验所有API的必需请求参数都已配置源数据，未配置时弹窗或抽屉提示用户配置

### 问题2：编辑用例保存报错
- **现状**：编辑用例保存时可能出现错误
- **需求**：修复保存逻辑，确保数据格式正确

### 问题3：页面跳转后URL未重定向
- **现状**：页面跳转后URL会变化，但这些URL未在路由中定义，刷新会报错
- **需求**：确保所有页面跳转都使用已定义的路由，或添加重定向规则

## 目标

1. 在执行用例前，系统 SHALL 校验所有API的必需请求参数都已配置源数据
2. 如果发现未配置的参数，系统 SHALL 弹窗或弹出抽屉让用户配置
3. 系统 SHALL 修复编辑用例保存的错误
4. 系统 SHALL 确保所有页面跳转使用正确的路由，刷新不会报错

## 验收标准

1. ✅ 执行用例前，系统检查所有API的必需请求参数是否都有字段映射
2. ✅ 发现未配置参数时，弹出配置界面（抽屉或弹窗）
3. ✅ 编辑用例保存功能正常工作，无错误
4. ✅ 所有页面跳转使用已定义的路由，刷新不会报错
