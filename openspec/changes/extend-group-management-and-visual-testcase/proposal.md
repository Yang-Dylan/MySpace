# Change: 扩展分组管理与可视化用例展示

## Why
当前系统虽然已支持API分组和字段映射，但存在以下体验和功能缺失：
1. 缺少分组维度的统一管理视图，用户无法在一个页面内查看分组下的所有接口和用例
2. 测试用例缺少直观的可视化展示，用户难以理解复杂用例的API调用关系和参数传递
3. 不支持条件执行，无法根据前置API的响应结果决定是否执行后续API
4. 上传API文档时的分组选择体验需要优化，支持新建分组

## What Changes

### 1. API文档上传增强
- 上传时可选择已有分组或新建分组
- 新建分组支持输入名称和描述

### 2. 分组列表与详情页面（新增）
- **分组列表页面**：展示所有分组，显示每个分组的接口数量和用例数量
- **分组详情页面**：包含两个Tab
  - **接口Tab**：分页展示该分组下所有API文档中解析出的接口列表，支持编辑接口参数和标签
  - **用例Tab**：展示和编辑使用该分组内API的测试用例

### 3. 用例可视化展示（新增）
- 点击用例进入可视化视图页面
- 采用**卡片流/泳道图**形式（相比流程图更适合线性API调用场景）
- 每个API显示为卡片，展示：
  - API名称、方法、路径
  - 关键参数（最多显示3个输入/输出参数）
  - 参数传递连线（从源API到目标API的字段映射）
- 支持查看和编辑字段映射关系

### 4. 条件执行功能（新增）
- 支持在用例中配置条件判断
- 条件基于前置API的响应字段值
- 支持单字段或多字段组合条件
- 条件运算符：等于、不等于、包含、大于、小于等
- 条件逻辑：AND、OR组合
- 条件不满足时可配置：跳过后续API / 标记用例失败 / 执行备选分支

## Impact
- 受影响的规范：
  - `api-doc-management` - API文档上传和分组管理
  - `test-case-generation` - 测试用例生成和条件配置
  - `visual-orchestration` - 可视化展示和编辑
- 受影响代码：
  - 后端：新增路由、模型字段、业务逻辑
  - 前端：新增页面（分组列表、分组详情、用例可视化）、路由调整
  - 数据库：test_case_apis表新增条件字段
- 依赖关系：
  - 扩展自 `api-grouping-and-field-mapping` change
