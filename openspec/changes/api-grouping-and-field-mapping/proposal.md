# Change: API分组管理与字段映射增强

## Why
当前系统存在以下问题需要解决：
1. API文档没有分组概念，无法区分不同项目或模块的API
2. 无法将常用接口（如获取token的接口）标记为公共组件供其他用例复用
3. 字段映射时缺少清晰的源参数分类（请求参数、响应参数、数据集参数）
4. API上传后缺少字段信息验证机制，可能导致不可用的API被使用
5. Swagger文档输出不完整，缺少详细的请求参数和响应参数描述

## What Changes
1. **API文档分组功能**
   - 上传API文档时需要选择或创建分组
   - 只有同分组的API才能组合成测试用例
   - 新增API分组管理功能

2. **API标签功能**
   - 支持为API打标签（如token、auth等）
   - 标签化的API可以在其他用例执行时被选择使用
   - 支持从标签API中获取字段值（如token）

3. **字段映射增强**
   - 源选择支持：当前选中的API列表 或 配置的数据集
   - 字段分类为：请求参数、响应参数、数据集参数
   - 参数可手动编辑或从上传文件中解析

4. **API可用性验证**
   - 解析API时提取请求和响应参数
   - 如无有效参数信息，标记API为"不可用"
   - 用户编辑完善后才可使用

5. **Swagger文档增强**
   - 完善所有接口的请求参数文档
   - 完善所有接口的响应参数文档
   - 使用Pydantic模型提供详细说明

## Impact
- 受影响的模块：
  - `api-doc-management` - API文档管理
  - `test-case-generation` - 测试用例生成
  - `test-execution` - 测试执行
- 受影响代码：
  - 后端：models, schemas, routers
  - 前端：API上传页面、测试用例创建页面
  - 数据库：新增表和字段
